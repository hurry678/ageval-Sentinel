## Purpose

集中声明与发现 Agent 接入类型及其能力标志，作为平台唯一事实来源，使新增一种 Agent 类型只需一处注册，替代散落各处的硬编码枚举、白名单与框架特判分支。

## Requirements

### Requirement: 适配器类型注册表单一来源

系统 SHALL 以一个适配器注册表作为 Agent 接入类型（adapter_type）的唯一合法来源。所有对"某接入类型是否合法/是否可运行/需要何种前置条件"的判断 MUST 从注册表派生，不得在多处重复硬编码同一集合。

#### Scenario: 合法性校验取自注册表

- **WHEN** 客户端提交带某 `adapter_type` 的 Agent 接入或审计请求
- **THEN** 系统依据注册表判定该类型是否已登记
- **AND** 未登记类型被拒绝并返回明确错误，已登记类型按其声明处理

#### Scenario: 已登记类型行为保持不变

- **WHEN** 使用现有已登记类型（ecommerce_demo、external_sdk、http_endpoint、openmanus）发起既有流程
- **THEN** 其接入、画像与审计的可观察行为与改造前一致

### Requirement: 通过能力标志消除框架特判

注册表中的每个适配器 SHALL 声明其能力标志（如是否需要镜像源、是否需要 hosted 模型运行时、所属框架标识、可运行/仅脚手架）。系统中与具体框架相关的分支 MUST 依据能力标志决策，不得直接比较具体 `adapter_type` 字符串（如 `== "openmanus"`）。

#### Scenario: 框架相关前置校验依据能力标志

- **WHEN** 审计前置检查判断某接入类型是否需要额外前置条件（如需要就绪的 hosted 模型）
- **THEN** 判断依据该适配器的能力标志
- **AND** 新增一个具有相同能力的适配器时无需修改该前置检查代码

### Requirement: 新增适配器类型的单点扩展

系统 SHALL 使新增一种 Agent 接入类型的改动收敛到注册表的一处登记。登记后，合法性校验、可运行性、前置条件与框架映射 MUST 自动生效，无需再改动分派、白名单或契约枚举等其他位置。

#### Scenario: 一处登记即端到端可用

- **WHEN** 开发者在注册表登记一个新适配器（含其能力标志与运行入口）
- **THEN** 该类型即被合法性校验接受
- **AND** 其接入白名单、可运行性与框架映射均按登记内容生效，无需改动其他文件

### Requirement: 框架识别到可运行适配器的映射可扩展

系统 SHALL 依据注册表声明的框架映射，将画像阶段识别出的框架解析为对应的可运行适配器类型。当识别框架已登记映射时 MUST 使用该映射，未登记时 MUST 回退到明确的通用类型而非静默误判。

#### Scenario: 已登记框架映射被采用

- **WHEN** 画像识别出某框架且注册表存在其到适配器类型的映射
- **THEN** 资产索引采用该映射的适配器类型

#### Scenario: 未登记框架显式回退

- **WHEN** 画像识别出的框架在注册表无映射
- **THEN** 系统回退到通用适配器类型并记录该回退，不将其误标为特定框架
