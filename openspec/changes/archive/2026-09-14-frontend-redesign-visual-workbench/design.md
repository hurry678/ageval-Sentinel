## Context

现状见 `proposal.md` - Why。技术约束:前端为 React18 + TypeScript + Vite6,图表用 echarts,图谱用 @xyflow/react,图标 lucide-react,路由用 HashRouter(桌面 webview 与打包 `app.html` 依赖 hash 路由)。设计令牌现集中在 `refinement.css`。后端为 FastAPI,前端经 Vite 代理 `/v1` 调用,受保护接口需 token。用户已拍板:**推倒重建** + **前端静默登录**。

## Goals / Non-Goals

**Goals:**
- 重建设计系统与全部页面/组件,达成图形化、最小输入、响应式、亮/暗主题、无障碍。
- 适配器/基准数据驱动,消除 `NewAudit.tsx` 的二值硬编码。
- 补齐执行期实时反馈、多轮趋势/轮次对比、报告导出。
- 无登录 UI 下经静默登录接入受保护接口。

**Non-Goals:**
- 不改后端审计/判定/攻击生成逻辑(那是独立的"检测能力"缺口线)。
- 不新增攻击场景覆盖。
- 不做多用户/权限 UI、不做真正的认证界面。
- 不引入新前端框架(仍 React/Vite)。

## Decisions

### D1. 推倒重建但复用运行时依赖
重写 `pages/*`、`components/*`、令牌与全局样式;保留并复用 echarts、@xyflow、lucide、Vite、HashRouter 与 `types.ts` 中的领域类型。**理由**:视觉与交互推倒,但底层数据契约(`api.ts` 端点、`types.ts`)稳定,复用可降低回归面。**备选**:换 Tailwind/组件库——否决,增加依赖与迁移成本,且现有 token 体系已足够。

### D2. 设计令牌 = CSS 变量 + `data-theme`
令牌集中在单一 CSS 文件的 `:root`,暗色主题以 `:root[data-theme="dark"]` 覆盖;主题选择写入 `localStorage` 并在启动时应用到 `<html>`。**理由**:零运行时开销、SSR 无关、切换即时。**备选**:CSS-in-JS 主题——否决,增加体积与复杂度。

### D3. 静默登录以固定 dev 身份获取 token
应用启动时,`session` 引导模块用预置 dev 账号调用现有登录端点取 token 存入内存/`localStorage`;首次若账号不存在则先注册再登录;401 时自动重取并重试一次。dev 凭据来自构建期环境变量(`import.meta.env`),不硬编码进产物明文。**理由**:后端认证不改,前端零 UI 接入。**备选**:后端加免认证开关——用户已选前端静默登录,否决。

### D4. 适配器/基准数据驱动 + 最小只读元数据端点
前端不再硬编码 benchmark/风险面;优先消费 `listAgents` 已返回的 `adapter_type`。推荐基准/风险面/runtime_mode 来自后端 `catalog.py` 的描述符——若现有 API 未暴露,则**新增一个只读端点** `GET /v1/catalog/adapter-types` 返回描述符映射。**理由**:满足"未知 adapter_type 也可用"契约,且只读、不改审计行为(符合 proposal 的后端不改行为约束)。**备选**:把元数据塞进 agent 列表响应——可行但耦合;单独只读端点更清晰。**风险见 R3。**

### D5. 执行期实时反馈基于增量轮询
无 SSE/WebSocket 基础设施时,执行页对审计状态与已完成场景结果做**增量轮询**,逐条点亮命中流;阶段时间线由状态机推导。**理由**:复用现有轮询,避免后端改造。**备选**:SSE——需后端改造,超出本期范围。**降级**:若后端不暴露逐条结果,则退化为阶段级进度 + 整轮出明细。

### D6. 报告导出走客户端
JSON 导出直接序列化报告数据;PDF 导出用专用打印样式 + 浏览器打印(`window.print`)。**理由**:避免引入重型 PDF 库(约束 calling_external_apis:优先无新依赖)。**备选**:jsPDF/pdfmake——否决,体积大且排版难控;若打印质量不足再评估。

### D7. 保留 HashRouter,重排路由
路由:`/`(概览)、`/agents`、`/agents/:id`、`/audits`、`/audits/new`、`/audits/:id`、`/reports`(报告中心,新增)、`/settings/models`;移除 `/login`。**理由**:hash 路由兼容打包 webview;新增报告中心承载跨审计对比与导出。

### D8. 图表与图谱统一主题层
所有 echarts 实例共享一个由设计令牌派生的 theme 对象;风险色板集中定义,标签/徽章/图表共用。攻击链用 @xyflow 有向图渲染。**理由**:满足"跨视图颜色一致"契约。

## Risks / Trade-offs

- **[推倒重建回归面大]** → 分能力分批交付(见 tasks 分组),每批保留/重写对应 Vitest;先搭壳与令牌,再逐页迁移,保持可运行。
- **[静默登录 dev 凭据泄露]** → 仅用于本地/dev;凭据经环境变量注入不写死明文;明确本期不适用于生产暴露环境(安全提醒:上线前必须换回真实认证)。
- **[D4 需后端只读端点,越出"前端-only"边界]** → 端点为纯只读、不触碰审计逻辑;若不允许改后端,则降级为前端从 agent 字段推导 + 内置默认映射(仍数据驱动于 agent,但推荐基准可能不全)。**需与用户确认,见 Open Questions。**
- **[D5 逐条实时依赖后端是否暴露增量结果]** → 若不暴露则降级为阶段级进度,契约中"实时命中流"以"轮询到结果即更新"满足,而非流式。
- **[PDF 打印排版]** → 打印样式需专门调校;先保证 JSON 导出与可打印布局,PDF 精细度作为次要目标。
