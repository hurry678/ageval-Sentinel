## Purpose

定义审计工作流的交互契约——向导式新建审计、数据驱动预填与最小输入、攻击集审阅授权,以及执行期的实时进度反馈,使用户以最少操作完成从配置到执行的闭环。

## ADDED Requirements

### Requirement: 向导式新建审计

新建审计 SHALL 以分步向导呈现(选择 Agent → 配置目标 → 生成攻击集),每步 MUST 有清晰的进度指示与前进/后退控制,且非法或缺失输入 MUST 阻止进入下一步并给出内联提示。

#### Scenario: 分步推进

- **WHEN** 用户完成"选择 Agent"步骤
- **THEN** 进入"配置目标"步骤,进度指示更新
- **AND** 未选择 Agent 时无法进入下一步

### Requirement: 数据驱动的适配器与基准

新建审计 SHALL 从后端获取可用 Agent 及其 `adapter_type`、推荐基准与风险面,并据此预填表单。界面 MUST NOT 对 adapter_type 或基准做仅支持两种类型的硬编码分支;新增一种适配器类型时 MUST 无需修改前端选择逻辑即可呈现。

#### Scenario: 选中 Agent 自动预填

- **WHEN** 用户选中某个 Agent
- **THEN** 表单按该 Agent 的 adapter_type 自动带出推荐基准与风险面

#### Scenario: 未知适配器类型可用

- **WHEN** 存在一个界面未预置的 adapter_type 的 Agent
- **THEN** 该 Agent 仍可被选择并按后端返回的元数据完成配置

### Requirement: 最小化输入的目标配置

配置目标步骤 SHALL 允许用户以可点选 chips 选择授权风险面、以卡片增删多个业务任务,并提供一键示例填充与强度选择。强度选择 MUST 实时预览将生成的攻击场景规模。

#### Scenario: 强度实时预览

- **WHEN** 用户调整攻击强度
- **THEN** 界面即时更新预计生成的攻击场景数量

#### Scenario: 增删业务任务

- **WHEN** 用户添加或删除业务任务卡
- **THEN** 提交的业务任务集合随之增减

### Requirement: 攻击集审阅与授权

生成攻击集后,系统 SHALL 以逐条可视卡片展示每条攻击的风险面、预测节点、路径与证据,用户 MUST 能按风险面筛选并逐条或批量授权,只有授权后方可启动正式审计。

#### Scenario: 授权后启动

- **WHEN** 用户完成攻击集授权
- **THEN** "启动审计"可用;未授权时不可启动

### Requirement: 执行期实时进度

审计执行中,界面 SHALL 呈现分阶段时间线(baseline→加固→复测)与逐条攻击的实时命中状态,MUST NOT 要求用户等待整轮结束才能看到任何进展。

#### Scenario: 实时命中流

- **WHEN** 审计正在执行且某条攻击得出结果
- **THEN** 该攻击在界面上即时更新为成功或被防住的状态
